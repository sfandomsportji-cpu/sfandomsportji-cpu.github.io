## 2. GitHub 자동화

### A. Daily Morning Edition (승인 요청)

- 파일: `.github/workflows/daily-edition.yml`
- 상태: **설정됨**
- 실행: **매일 08:00 KST**
- 수동 실행: 가능 (`workflow_dispatch`)
- 모델: **Anthropic Claude**
- 실행 구조:
  1. GitHub Actions 시작
  2. `ANTHROPIC_API_KEY`로 Claude 호출
  3. 모닝 에디션 4개 슬롯 초안 생성
  4. 이전 에디션 Archive 보존
  5. 새 브랜치 생성
  6. 승인용 Pull Request 생성
  7. Ji가 Merge하면 게시 / Close하면 폐기
- 자동 Merge: **하지 않음**
- 자동 게시: **하지 않음**
- 텔레그램 알림: 관련 Secret이 등록된 경우에만 동작

#### 필수 외부 설정

- `ANTHROPIC_API_KEY`: GitHub Repository Secret 등록 필요
- GitHub Actions의 **Allow GitHub Actions to create and approve pull requests** 설정 필요
- 위 두 항목은 현재 연결된 GitHub 도구에서 Secret 값이나 계정 UI 저장 상태를 직접 검증할 수 없음

#### 실행 검증 상태

- PR #159를 통해 OpenAI 기반 자동화 → Claude 기반 자동화로 전환 완료
- 최신 GitHub Pages 배포는 성공 확인
- Claude Daily Morning Edition 자체는 **성공 실행 기록을 아직 확인하지 못함**
- 따라서 첫 성공 실행 전까지 운영 상태는 **구성 완료 / 실전 검증 대기**로 본다

## 3. ChatGPT 내부 예약 작업 — 현재 활성

현재 활성 예약 작업은 **3개**다.

| 작업 | 일정 | 상태 | 알림 |
|---|---|---|---|
| 인스타 10릴스 사전회의 | 매일 08:00 KST | 활성 | ChatGPT 알림 OFF |
| Google Blogger 3건·각 7장 품질검수 | 매일 09:30 KST | 활성 | ChatGPT 알림 OFF |
| 비침습 BCI 주간 읽을거리 | 매주 금요일 08:00 KST | 활성 | 알림 ON / 이메일 ON |

### 인스타 10릴스 사전회의

- 하루 10개 Reels 후보 사전 검토
- 콘텐츠 가치, 글로벌 확장성, 중복도, 첫 1~2초 훅, 시청 유지, 전환 가능성 평가
- 영문 70% + 한글 30% 키워드
- 사용자 승인 전 자동 발행 금지

### Google Blogger 3건·각 7장 품질검수

- 하루 3개 독립 원고
- 각 글은 실제 7장급 장문
- 제목, 한줄 요약, 흐름, 본문 밀도, 데이터, 이미지/도표, 결론, 해시태그, 라벨 검수
- 기준 미달 시 자동 수정하지 않고 먼저 보고
- 명시적 승인 전 실제 발행 금지

### 비침습 BCI 주간 읽을거리

- 매주 최근 7일 비침습 BCI 연구 정리
- EEG / MEG / fNIRS / non-invasive neural decoding 포함
- 논문 원문·공식 자료 우선
- 과장된 홍보자료 제외

## 6. 스포츠 분석 운영

스포츠 분석은 자동 게시 시스템과 분리한다.

- 담당: Kairo
- 사용자 최종 선택 원칙
- 최신 경기·선발·부상·라인업·현지 이슈를 실시간 검증
- 야구: 선발 이름, ERA, 최근 등판, 부상, 투구수, 휴식, 상대전, 팀 타격지표
- 축구: 예상 선발, 결장/징계, 동기부여, 최근 흐름, H2H
- 후보군을 먼저 제시하고 최종 선택은 Ji가 결정
- 사이트 자동 발행과 스포츠 분석 판단을 직접 연결하지 않음

## 7. 현재 핵심 체크포인트

1. **Claude 모닝 에디션 자동화 첫 성공 실행 확인**
2. `ANTHROPIC_API_KEY` 등록 여부 사용자 화면 확인
3. GitHub Actions PR 생성 허용 설정 저장 여부 확인
4. 첫 PR 생성 → 콘텐츠 검수 → Merge → 사이트 반영까지 1회 전체 사이클 검증
5. 검증 전에는 자동화를 '완전 정상 운영'으로 표시하지 않음

## 8. 현재 운영 결론

현재 SFANDOM은 자동화를 무조건 늘리는 단계가 아니라 **역할 분리 + 승인형 자동화** 구조로 전환 중이다.

- **Claude:** 코드와 GitHub 자동화
- **Kairo:** 경영, 콘텐츠, 스포츠 분석, 사건·법률, 유지보수 검수
- **Ji:** 최종 승인과 운영 결정

자동화는 사람의 최종 승인 없이 배포·발행하지 않는 것을 기본 원칙으로 한다.
