# SFANDOM 3종목 경기정보 수집·시간검증·배포안전 정책 v1.0

상태: **시범 구현 / 미승인 / 사이트 미적용**  
대상: 축구·농구·야구. 분석·픽 판단은 운영자 책임; 경기 상태 데이터 수집과 검증은 보조 시스템 책임.

## 1. 절대 원칙

- 새 코드를 프로덕션 main에 자동 반영하지 않는다. 공개 페이지의 원본/생성 HTML을 이 작업으로 변경하지 않는다.
- 크론 예약은 **수집·감사 전용**이고, 사이트 빌드/게시/푸시를 실행하지 않는다.
- 수집 데이터는 NOT_APPROVED이며 운영자 승인 전까지 사이트에 출력할 수 없다.
- 시간 표기는 원본 발표시각(출처 타임존), 수집시각(UTC), 확인시각(KST), 경기장 현지 일자, KST 경기 일자를 분리한다.
- **날짜만으로 경기 식별 금지.** 동일 일자 더블헤더, 심야 축구, NBA 원정 경기에서 오매칭 위험. 종목|제공자|이벤트ID 사용.
- 공식 부상 리포트는 **선발 라인업이 아니다**. 별도 공식 선발 근거 없으면 선발 확정 표기 금지.
- 보이지 않는 선수·누락된 팀·미제출 구단을 자동으로 '출전 가능' 처리하지 않는다.
- 정보 검증 실패·시간 불일치·스키마 변경 시 **기존 데이터만 보존**, 최신으로 표기하거나 게시하지 않는다.
- 수집처 이용약관·제공권한·재배포 권리를 확인한 범위 안에서만 활용한다.

## 3. 단계별 안전장치

1. **1순위:** NBA 공식 부상 페이지에서 최신 공식 PDF 링크 검증. 허용 도메인과 파일명, 발표시각, PDF 헤더/크기 검사.
2. **2순위:** NBA 공식 사이트의 별도 *목록 URL*을 다시 확인해 공식 PDF 다운로드 재시도. **같은 NBA PDF의 또 다른 경로이므로 독립적인 교차검증 근거는 아님.**
3. **3순위:** 둘 다 실패하면 마지막 정상 감사 스냅샷 보존 + STALE/NOT_APPROVED/public_display_allowed=false. 사용자 공개 화면에는 추후 **'현재 출전 정보를 확인하지 못했어요'**를 표시하도록 연결.

모든 예외는 GitHub Actions 실패로 가시화. 오류를 숨겨 정상처럼 표시하지 않는다.

## 4. 구분 표준 (NBA 공식 출전 상태)

- 녹색 **출전 예정** = 공식 Probable. 경기 실제 출전 확정 아님.
- 파란색 **출전 가능** = 공식 Available. 선발 출전 확정 아님.
- 빨간색 **출전 불가** = 공식 Out.
- 회색 **출전 미정 / 출전 불확실 / 확인 중** = Questionable/Doubtful/미제출/상충·누락 자료.
- 해당 NBA 부상 PDF에 등장하지 않았다는 이유만으로 선수 상태를 추정하거나 녹색·파란색으로 표시하지 않는다.
- 공식 선발명단(Lineup)은 별도의 공식 데이터가 있어야 제공한다.

## 5. 날짜·시간 검증

- 축구: Europe/Madrid 같은 경기장 실제 IANA 시간대와 KST 날짜를 분리한다. 새벽 경기 또는 국제대회 날짜 이월에 주의.
- 농구: 미국 동부시간(부상 PDF의 ET)과 경기장 시간대, UTC, KST를 분리한다. DST 전환을 자동 검증한다.
- 야구: MLB 미국 현지 날짜와 KST 날짜가 다를 수 있다. **더블헤더**는 날짜가 같아도 이벤트 ID가 달라야 한다. KBO와 NPB는 Asia/Seoul/Asia/Tokyo 사용.
- ISO 입력에 연도 또는 UTC offset이 없으면 거부. 현지시각만 제공되는 경우 IANA 타임존 필수이며 DST 존재하지 않는 시각은 거부, 중복되는 시각은 명시적 fold 필요.
- GitHub 예약 3,13,23,33,43,53 * * * * 은 **10분 간격 요청이지 정시 실행 보장이 아니다.** 체크 간격 >22분은 별도 경보 표시, 최신성은 원문 발표시각과 실제 수집시각으로 계산한다.
- 데이터 수집이 늦었다고 발표시각을 수집시각으로 덮어쓰지 않는다.
- 모든 표시 일자는 KST로 명시한다. 일자 변경 자정 전후(23:59→00:00), DST, 연말, 더블헤더 단위 테스트 필수.

## 6. 운영 승인 흐름

공식 출처 확인 → 값/시각 검증 → 이전 이력과 비교 → 비공개 초안 → 운영자 검토 → 별도 승인 → 공개용 데이터 반영 → 수동 배포.

실패 시 해당 자료는 승인 불가이며 **추정·오보를 자동으로 채우지 않는다**. 정정 시 직전 출처, 변경 전후 상태, 공식 확인시각을 남긴다.

## 7. 기술적 범위

- .github/workflows/nba-injury-watch.yml: 수집만. contents: read, actions: read. PR에서는 단위 테스트만, 기본 브랜치 병합 전 10분 예약 실행 미활성.
- src/tools/nba_injury_monitor.py: 공식 NBA PDF 확인과 미승인 JSON 감사 저장. 생성된 JSON은 Actions artifact(보존 2일), **사이트 저장소에 커밋되지 않음**.
- src/tools/injury_failover.py: 위험시 3순위 봉쇄.
- src/tools/sports_clock.py: 종목 공통 시간 정규화와 신선도 검사.
- tests/: 네트워크 없는 상태 검사. 운영 반영 전 실제 공식 PDF의 필드 위치·동작과 샘플 리그 경기 검증이 **추가로 필요**.
