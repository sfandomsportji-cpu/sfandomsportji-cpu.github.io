# SFANDOM 영상 제작 표준 워크플로우 v1.0

최종 합의일: 2026-09-17

## 목적
네이버 블로그, Instagram Reels, SFANDOM 사이트에서 반복적으로 필요한 영상 작업을 안정적으로 수행하기 위한 고정 절차다. 소스 선정, 편집점 확정, 추출, 검수, 병합을 분리해 불필요한 재작업과 크레딧 낭비를 막는다.

## 1단계 — 소스 섭외 및 링크 고정 (Ji)
- 사용할 영상은 Ji가 직접 섭외한다.
- 최종 사용할 웹 영상 링크를 Ji가 고정한다.
- 링크 고정 전에는 Kairo가 임의로 다른 영상이나 대체 소스를 끼우지 않는다.
- 공식 홈페이지, 공개 영상 등 실제 접근 가능한 소스를 우선한다.

## 2단계 — 편집점 공동 선정 (Ji + Kairo)
- Ji와 Kairo가 함께 영상의 시작점과 종료점을 찾는다.
- 임팩트 있는 시작 장면, 자연스러운 종료 지점, 전환 타이밍, 실황음 활용 구간을 함께 검토한다.
- 편집점은 타임코드로 최종 확정한다.
- 최종 편집점이 확정되기 전에는 원본을 임의로 자르거나 최종 렌더링하지 않는다.

## 3단계 — 확정 구간 추출 (Kairo)
- Kairo는 확정된 타임코드 구간만 추출한다.
- 추출본은 각각 별도 파일로 보관한다.
- 이 단계에서는 최종 병합을 하지 않는다.
- 원본에 경기 실황 오디오가 있으면 우선 유지한다. 오디오 사용이 적절하지 않거나 불가능하면 무음으로 처리한다.

## 4단계 — 병합 전 공동 검수 (Ji + Kairo)
- 추출이 끝나면 Ji와 Kairo가 다시 모여 추출본을 확인한다.
- 확인 항목: 영상 순서, 길이, 시작/종료 프레임, 화면 전환, 실황음/무음, 불필요 장면 포함 여부.
- Ji의 최종 승인 전에는 병합 렌더링을 진행하지 않는다.

## 5단계 — 최종 병합 및 렌더링 (Kairo)
- 승인된 추출본만 지정 순서대로 병합한다.
- 해상도, 프레임레이트, 오디오 조건을 맞춘 뒤 MP4로 렌더링한다.
- 결과 파일이 실제로 생성되고 재생 확인이 끝난 뒤에만 “완료”로 보고한다.
- 파일 생성 전에는 완료했다고 말하지 않는다.

## 채널별 기본 적용
- Instagram Reels: 약 10초 전후, 세로 9:16 우선. 전날 경기/스포츠 이슈 중 하나를 선택해 매일 다른 분위기로 제작한다.
- 네이버 블로그: 필요 시 같은 원본에서 블로그용 규격으로 별도 출력한다.
- SFANDOM 사이트: 사이트/커뮤니티용 비율과 길이에 맞춰 별도 출력한다.
- 동일 원본을 활용해도 채널별 최종본은 별도로 렌더링한다.

## 웹 영상 추출 원칙
- “Opera 브라우저 자체”, “Opera 커넥터가 볼 수 있는 범위”, “실제 영상 파일 추출 단계”를 서로 구분한다.
- 웹영상 추출과 편집은 별도 단계로 취급한다.
- 막힐 경우 원인을 다음 중 하나로 명확하게 보고한다: 미디어 주소 미노출 / 스트림 접근 불가 / 로그인·DRM / 파일 확보 완료.
- DRM, 로그인, 접근통제 우회는 하지 않는다.

## 커넥터 확인 원칙
- Ji가 연결 상태 캡처를 제공하면 그 화면을 우선적인 실제 UI 상태로 받아들인다.
- Kairo는 캡처를 무시하고 “연결 안 됨”이라고 단정하지 않는다.
- 화면상 연결 상태와 백엔드 도구 상태가 다르면 두 상태를 분리해 교차확인한다.

## Runway 크레딧 운영 원칙
- Runway는 Ji가 명시적으로 승인했을 때만 사용한다.
- 실행 전 예상 크레딧과 목표 결과물을 먼저 확인한다.
- 불필요한 테스트 영상, 콘셉트 이미지, 사전 일러스트 생성은 금지한다.
- 월 운영 목표는 30초 영상 2편 확보를 기준으로 한다.
- 생성 이후 컷 편집, 병합, 리프레임 등 가능한 작업은 로컬 처리한다.

## 핵심 체크포인트
1. 링크 고정 전 임의 소스 교체 금지
2. 편집점 확정 전 추출 금지
3. 추출 후 바로 병합 금지
4. 병합 전 공동 검수 필수
5. 최종 승인 후 렌더링
6. 실제 파일 생성·재생 확인 후에만 완료 보고
7. Runway 불필요 호출 금지
