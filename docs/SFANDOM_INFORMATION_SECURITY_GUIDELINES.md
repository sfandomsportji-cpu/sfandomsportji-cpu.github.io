# SFANDOM Information Security Guidelines

SFANDOM protects its analysis standards, unpublished content, operational documents, personal data, and account information under the following principles.

1. **Minimum disclosure:** Only approved, already-public information may be shared externally. Unclear information is treated as confidential.
2. **Minimum access:** Repository, application, and collaborator permissions are limited to what is necessary and reviewed regularly.
3. **Explicit approval:** Publication, external transmission, guideline changes, and production deployment require authorized review.
4. **Secret protection:** Passwords, tokens, recovery codes, cookies, session identifiers, personal data, and raw security logs must never be committed to GitHub.
5. **Safe changes:** Repository updates use a separate branch and pull request. Direct unreviewed production changes are prohibited.
6. **Incident response:** On suspected unauthorized access or disclosure, stop further transmission, preserve objective evidence, notify the authorized owner, revoke exposed access, and document the response. Do not speculate about identities or causes.
7. **Public reporting:** Public alerts contain no sensitive security details. Detailed evidence remains in restricted internal storage.

**Core rule:** Minimum disclosure · Minimum privilege · Explicit approval · Evidence preservation · No unsupported assumptions
