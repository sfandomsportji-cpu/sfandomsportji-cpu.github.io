# SFANDOM SITE INSPECTION — 2026-09-08 #01

- **KST date:** 2026-09-08
- **Scope:** Home visitor counter / CounterAPI integration / collision & failure-isolation check
- **Result:** PASS
- **Decision:** **KEEP AS-IS — no production code change required**

## 1. Inspection target

현재 홈 헤더의 `VISITORS` 카운터가 정상적으로 증가하는 상태에서, CounterAPI 연동 구조가 메인 페이지와 충돌할 가능성이 있는지 코드 기준으로 재점검했다.

확인 대상:

- `visitor-counter-bootstrap.js`
- `visitor-counter.css`
- `signature-moments.js`
- `index.html`
- GitHub Pages 최근 배포 상태

## 2. CounterAPI integration

현재 카운터는 다음 구조를 사용한다.

- Provider script: `https://counterapi.com/c.js?ns=sfandom.com`
- Key: `sfandom-global`
- Action: `view`
- CounterAPI 기본 스타일 미사용: `noCss=true`
- 아이콘/링크/애니메이션 미사용: `noIcon=true`, `noLink=true`, `noAnim=true`

현재 `unique` 속성은 지정하지 않는다. 따라서 기본 동작은 방문/view 이벤트 누적 방식이며, 이것은 **집계 기준의 차이일 뿐 메인 페이지와의 충돌 요인이 아니다.**

즉 현재 `VISITORS` 값은 엄밀한 고유 방문자(UV) 수가 아니라 누적 방문 이벤트에 가까운 지표로 해석한다.

## 3. Duplicate-load protection

카운터 부트스트랩에는 중복 삽입 방지 장치가 있다.

- `[data-sf-visitor-counter]` 존재 여부 확인 후 DOM 중복 생성 방지
- `script[data-sf-counterapi-script]` 존재 여부 확인 후 CounterAPI 스크립트 중복 로드 방지
- `link[data-sf-visitor-counter-css]` 존재 여부 확인 후 CSS 중복 로드 방지

`index.html`은 CounterAPI를 직접 중복 로드하지 않고 `signature-moments.js`를 통해 카운터 모듈을 불러오는 구조다.

## 4. Failure isolation

외부 CounterAPI 응답이 늦거나 실패해도 메인 페이지 전체가 멈추지 않도록 분리되어 있다.

- CounterAPI 외부 스크립트는 `async` 로드
- 숫자가 준비되기 전 카운터만 `hidden`
- 숫자 감시용 `MutationObserver`는 최대 10초 후 종료
- 카운터 실패 시 네비게이션, 영상, 콘텐츠 렌더링을 중단시키는 로직 없음

따라서 외부 카운터 서비스 장애가 발생하더라도 영향 범위는 카운터 표시 자체로 제한되는 구조다.

## 5. CSS / layout isolation

카운터 스타일은 `sf-visitor-counter*` 전용 클래스 네임스페이스를 사용한다.

기존 공통 헤더 클래스(`site-header`, `nav`, `brand`, `header-cta`)를 덮어쓰는 방식이 아니며, CounterAPI 자체 CSS도 비활성화되어 있어 외부 위젯 스타일이 SFANDOM 헤더에 개입할 위험을 낮춘 상태다.

모바일에서는 카운터만 별도 위치 규칙을 사용하며 현재 사용자 화면에서 실제 표시와 카운팅이 정상적으로 확인되고 있다.

## 7. Decision

**현재 카운터 코드는 수정하지 않는다.**

정상 작동 중인 기능을 예방 명목으로 다시 손대는 것이 오히려 회귀(regression) 위험을 높일 수 있으므로, 현 구조를 고정한다.

향후 실제 오류가 재현될 때만 다음 순서로 대응한다.

1. 원인 진단
2. 영향 범위 확인
3. 최소 수정
4. 중복/잔여 참조 검사
5. GitHub Pages 배포 성공 확인
6. 실제 화면 재검증

## 8. Operating rule confirmed

SFANDOM 코드 운영 원칙:

- 작동하는 기능은 이유 없이 다시 고치지 않는다.
- 필요 없는 기능은 숨겨두지 않고 제거한다.
- 임시 우회 코드와 중복 로더를 누적하지 않는다.
- 외부 의존 기능은 메인 기능과 장애 범위를 분리한다.
- 현재 `VISITORS`는 방문 이벤트 지표로 사용하고, 향후 고유 방문자 KPI가 필요하면 별도 설계 후 도입한다.

**Final status: PASS / KEEP AS-IS**
